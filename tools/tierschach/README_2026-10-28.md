# Projekt Tier-Schach

Animierte 3D-Schachfiguren (Tiere), je Weiß und Schwarz, Animationen `Idle` und `Walk`.
Ergebnis: `pieces/<figur>_<weiss|schwarz>.glb` (~5000 Dreiecke, Textur 1024 JPEG, Augen als eigene Geometrie,
je ~0,7–1 MB). Erzeugt am 2026-10-28 mit dem Claude-Plugin **gb10-assets** (ohne die alte TRELLIS-Pipeline).

| Figur | Tier | Merkmal | Bewegung |
|---|---|---|---|
| Bauer | Hase | Eichel | hüpft |
| Springer | Pony | | läuft (Vierbeiner) |
| Läufer | Schaf | Bischofsmitra | läuft (Vierbeiner) |
| Turm | Schnecke | Zinnenkranz auf dem Haus | gleitet (Kriechwelle) |
| Dame | Giraffe | kleine Krone | läuft (Vierbeiner) |
| König | Elefant | Krone und Königsmantel | läuft auf zwei Beinen |

## Wichtig vorab

- **Nur ein Blender-Prozess lokal zur Zeit.** Der Rechner hat 14 GB RAM; 12 parallele Blender-Prozesse
  haben den OOM-Killer ausgelöst (Browser usw. wurden beendet). `tools/faces.py` rendert deshalb alle
  Figuren in einem Prozess.
- Lokaler Blender: `~/blender/bin/blender -b --factory-startup --python <skript> -- <args>`.
- GB10-Server: führt immer nur einen Job aus. Mitgelieferte Skripte liegen dort unter
  `/app/tools/blender/scripts/` (u.a. `glb_post`, `tex_eyes`, `tex_eyecover`, `eye_geo`, `rig_biped`,
  `rig_quadruped`). Eigene Skripte (`eyes_chain.py`, `rig_snail.py`) als Datei in `files` mitschicken und mit
  diesem `code` starten:
  ```python
  import runpy, sys; sys.argv=["x.py"]+sys.argv[1:]; runpy.run_path("<datei>.py", run_name="__main__")
  ```
- Achsen: Blender Z oben, Figur blickt nach −Y. glTF Y oben, Figur blickt nach +Z. `board_preview.py` dreht
  die weißen Figuren um 180°.

## Neu erzeugen

Ein Durchlauf je Figur und Farbe; `F=bauer`, `C=weiss` als Beispiel. Wer nur etwas ändern will, steigt beim
passenden Schritt ein – alle Zwischenstände liegen in `work/`.

1. **Mesh** (GB10, `image_to_3d`): `image=../images/${F}_${C}.png, seed=42, max_faces=10000, texture_size=2048`
   → `work/$F/raw_$C/model_42.glb`. Pixal3D übernimmt die Kameraperspektive des Fotos, das Mesh steht also
   schräg (wird in Schritt 2 korrigiert).
2. **Vorbereiten** (lokal):
   ```
   blender -b --python tools/prep.py -- work/$F/raw_$C/model_42.glb work/$F/prep_$C.glb --yaw <yaw> [--cut-back 0.20]
   ```
   Dreht um Z, entfernt freischwebende Bruchstücke, reduziert auf 5000 Dreiecke. Neuen yaw finden:
   `tools/yawsweep.sh work/$F/raw_$C/model_42.glb sweep.png 20 25 30 35` (Vorder- und Seitenansicht je Wert).
   Fallstrick: `prep.py` muss `rotation_mode = "XYZ"` setzen, weil der glTF-Import Quaternionen einstellt –
   sonst wirkt `--yaw` nicht und die Figuren bleiben dreiviertel gedreht (so passiert im ersten Durchlauf).
3. **Augen** (GB10, eigener Code `tools/eyes_chain.py`, `files=[tools/eyes_chain.py, work/$F/prep_$C.glb]`):
   ```
   args: prep_$C.glb ${F}_$C [--eyes-json <json>] [--find-opts=--eyes x,h,v;x,h,v]
   ```
   Kette: `glb_post --emission 0 --tex 1024` → `tex_eyes` (gemalte Augen suchen) → `tex_eyecover` (übermalen)
   → `eye_geo` (Augen aus Geometrie: Weiß, Pupille, Glanzpunkt). Ergebnis `${F}_${C}_eyes.glb` →
   `work/augen/${F}_$C.glb`, `${F}_${C}_eyes.json` → `work/augen/${F}_$C.json`, `${F}_${C}_post.glb` →
   `work/$F/post_$C.glb`.
   - **Exakt reproduzieren:** immer `--eyes-json work/augen/${F}_$C.json` (Datei mitschicken).
   - **Automatisch:** ohne Optionen; danach mit `tools/faces.py` prüfen – tex_eyes nimmt gern Flecken auf Kopf
     oder Fühlern.
   - **Hinweis:** `--find-opts=--eyes ...` (genau so, mit `=`); Werte liefert
     `blender -b --python tools/eyepick.py -- work/$F/prep_$C.glb - --pick "fx,fh;fx,fh"`.
     Hilft nur, wenn die echten Augen unter den gefundenen Flecken sind.
   - **Von Hand:** Raster ansehen `blender -b --python tools/eyepick.py -- work/$F/prep_$C.glb grid.png`
     (rote Linien 0.0, 0.1 …, blaue 0.05 …), Augenmitten ablesen, dann
     `blender -b --python tools/eyes_json.py -- work/$F/post_$C.glb eyes.json --pick "fx,fh;fx,fh" --r 0.035`
     und mit `--eyes-json eyes.json` laufen lassen.
   - Größe/Abstand/Höhe der Augen ändern: `r` bzw. `c` in der JSON anpassen, oder `--geo-opts "--size … --apart …
     --drop …"` (Optionen von `eye_geo`, Hilfe per `job_status` eines `--help`-Jobs). Bisher ohne `--geo-opts`.
4. **Rig + Animation** (GB10): Befehl aus der Tabelle mit `work/augen/${F}_$C.glb` als Eingabe und
   `${F}_$C.glb` als Ausgabe → `pieces/`. Die Rigs hängen die Augen-Objekte (`Eye*`) an den Kopfknochen.
   Turm: `tools/rig_snail.py` mitschicken und per runpy starten (Haus samt Turm starr, Kriechwelle in der
   Sohle). Lokal geht auch `tools/rig_snail.sh in.glb out.glb --landmarks turm --walk 0.8 --height 0.78`.
5. **Kontrolle** (lokal, nacheinander):
   ```
   blender -b --python tools/faces.py -- gesichter.png pieces/*.glb
   blender -b --python tools/views.py -- pieces/X.glb front.png            # vorn/rechts/hinten/links
   blender -b --python tools/views.py -- pieces/X.glb walk.png --action Walk --frames 0,7
   blender -b --factory-startup --python tools/board_preview.py -- pieces brett.png --view seite|figuren|weiss|nah_weiss|nah_schwarz --res 1400x875
   ```

## Doku-Medien (`../docs/`, für die README der App smChess3d)

| Datei | Erzeugung |
|---|---|
| `vorlagen.jpg` | Kontaktblatt der Bildvorlagen (ändert sich nur mit neuen Vorlagen) |
| `figuren.mp4`, `figuren.webp` | `tools/figuren_video.py` (Blender, ~35 min CPU, allein laufen lassen) |
| `screenshot.jpg` | `tools/doku/shot.mjs` (Playwright, App-Partie nach 6 Zügen, 1600×900) |
| `spiel.mp4`, `spiel.webp` | `tools/doku/video.mjs` (Playwright, bildweise mit gesteuerter Uhr, 1280×720, 30 fps) |

```
# Figuren-Video
blender -b --factory-startup --python tools/figuren_video.py -- pieces frames/          # --still 60 zum Testen
ffmpeg -framerate 30 -i frames/%04d.png -c:v libx264 -preset slow -crf 20 -pix_fmt yuv420p -movflags +faststart ../docs/figuren.mp4
ffmpeg -i ../docs/figuren.mp4 -vf "fps=15,scale=600:-2:flags=lanczos" -c:v libwebp_anim -quality 55 -compression_level 6 -loop 0 ../docs/figuren.webp

# App-Aufnahmen: Checkout von smChess3d mit den neuen pieces/, dort npm ci, Server auf Port 3124
(cd $APP && PORT=3124 node server.js &)
APP=$APP node tools/doku/shot.mjs ../docs/screenshot.jpg
APP=$APP node tools/doku/video.mjs rec/        # ~5 min, ~1100 PNGs
ffmpeg -framerate 30 -i rec/%05d.png -c:v libx264 -preset slow -crf 22 -pix_fmt yuv420p -movflags +faststart ../docs/spiel.mp4
ffmpeg -framerate 30 -start_number 568 -i rec/%05d.png -vf "fps=12,crop=692:488:274:226,scale=600:-2:flags=lanczos" \
       -c:v libwebp_anim -quality 75 -compression_level 6 -loop 0 ../docs/spiel.webp   # Ausschnitt: Rochade bis Ende
```

Die Partie ist fest vorgegeben (1. e4 e5 2. Sf3 Sf6 3. Lc4 Sc6 4. O-O Sxe4 5. Lxf7+ Kxf7 6. Sc3 d5): Weiß per
Mausklick, Schwarz über einen Ersatz-Worker statt der Engine (`fakeEngine` in `tools/doku/common.mjs`; die App
erwartet Züge als `{from, to}`). Nicht parallel zu Blender aufnehmen: die App-Animationen hängen an der Bildrate,
bei voller Last bleiben Züge scheinbar stehen.

## Bekannte Eigenheiten

- Pony und Giraffe drehen in den Vorlagen den Kopf zur Kamera; der Körper steht gerade, der Kopf bleibt leicht
  seitlich gedreht.
- Weiß und Schwarz haben eigene Meshes, die Formen unterscheiden sich daher leicht.
- Schwarzer Elefant: alle Seeds erzeugten einen sehr langen Schwanz → `--cut-back 0.20`.
- Elefantenrüssel steht nach vorn statt eingerollt.
- Schwarze Schnecke: Augen (automatisch) etwas größer als bei der weißen.
